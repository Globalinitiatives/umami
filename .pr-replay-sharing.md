Implements #23.

## Problem

A replay recording could not be shared outside GMAnalytics. The Replays modal
was reachable only from an authenticated session, and the replay data endpoint
rejected any request without one:

```
GET /api/websites/{websiteId}/replays/{visitId}   (no auth)  ->  HTTP 401
```

The route is guarded by `canViewAuthenticatedWebsite`, which hard-requires
`auth.user` and ignores share tokens entirely. A public share framework already
existed for 15 report pages; replays were simply not wired into it.

There is no video file to extract. `ReplayPlayer` reconstructs the session from
an rrweb event array at render time, so the shareable unit is the player plus
its event feed.

## Design

A new `SessionReplayShared` table, modelled on the existing
`SessionReplaySaved`, stores one row per shared replay with a `slug`, an
internal `note`, `expiresAt`, and `revokedAt`.

The security boundary is `canViewSharedReplay` in `src/permissions/share.ts`. It
accepts either a logged-in owner with website access, or a share token that is
bound to the same website **and** the same `visitId`, whose row is neither
revoked nor expired. Because the token carries a single visit, one link can only
ever open one recording.

Expiry and revocation are read from the row rather than trusted from the token,
so a revoked link dies immediately instead of living out the token's remaining
lifetime. The slug is part of the token, so re-sharing rotates it and retires
the previous token.

## Changes

- `prisma`: new `SessionReplayShared` model + migration `27`.
- `src/queries/prisma/sessionReplayShared.ts`: create (upsert), lookup, revoke,
  list, and replay-scoped token minting with `1h / 24h / 7d` durations.
- `src/permissions/share.ts`: `canViewSharedReplay`.
- API: `POST/GET /websites/{id}/replays/shared`,
  `GET/DELETE /websites/{id}/replays/shared/{replayId}`,
  `GET /share/replay/{slug}` (slug to token exchange).
- The existing replay data route now also accepts a valid share token; owner
  access is unchanged.
- Public page `/share/replay/{slug}` renders the same `ReplayPlayer` as the
  modal, with no session info, save, or close affordances.
- Replays page gains a `Shared` tab beside `Saved`, listing only shared replays
  with their note, share time, expiry, and a revoke action.
- Share dialog in the replay modal collects the internal note and expiry, and
  returns a copyable link. The note is never shown on the public page.

## Verification

- `canViewSharedReplay`: 13 new tests covering owner access, wrong visit, wrong
  website, missing `visitId` (a website-wide token cannot reach replays),
  expiry including the exact boundary, immediate revocation well inside the
  token lifetime, missing record, and mismatched rows. 19/19 pass in the file.
- Migration applied to a real PostgreSQL 14 cluster: 8/8 checks confirm the
  unique slug, the one-share-per-website+visit constraint, the foreign key and
  its cascade, the non-null `expiresAt`, and the 500-character note cap.
- `tsc --noEmit`: no new errors. Four pre-existing failures remain
  (`EventsTable` `flexWrap`, an over-deep type instantiation, and three
  `@umami/api-client` / `@umami/mcp` module resolutions).
- Full suite: 23 failures, identical to `origin/master` — all pre-existing
  rebrand leftovers such as an `umami_` prefix assertion. Zero introduced.
- `biome check` clean on all touched files.

Live verification of the shared link is left to review, since it needs a real
session in the browser.

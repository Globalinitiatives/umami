Fixes the three UI bugs found in the replay share flow on live.

## 1. Share and Save dialogs were too narrow

Both were compressed to a fraction of their intended size. The cause is not
height: `Popover`'s popup ships with a fixed `w-72` (288px) class, and the
`style={{ width: ... }}` I had put on the inner `Dialog` set the width of a
nested element, so the popover stayed at 288px regardless.

The width has to go on the `Popover` itself:

```diff
-<Popover side="bottom" align="end">
-  <Dialog title={t(labels.shareReplay)} style={{ width: '360px' }}>
+<Popover side="bottom" align="end" className="w-96">
+  <Dialog title={t(labels.shareReplay)}>
```

Verified that `cn` (tailwind-merge) resolves the conflict in favour of the
override: given the popover's base classes plus `w-96`, the result is
`... w-96` with `w-72` removed, so the popup renders at 384px. A conflicting
utility is not appended alongside the base one.

The same fix applies to the Save dialog, which had the identical problem at
`width: 300px`.

## 2. `message.undefined` after saving a share link

`replayShared` and `replayRevoked` existed in `public/intl/messages/en-US.json`
but were never added to the `messages` map in `src/components/messages.ts`, so
`messages.replayShared` was `undefined` and rendered as `message.undefined`.

Two problems, both fixed:

- Added both keys to the `messages` map.
- The call site was also wrong: `t(\`message.${messages.replayShared}\`)`
  double-prefixed, since `messages.*` already holds the full `message.*` path.
  Corrected to `t(messages.replayShared)`. Grepped for the same
  `message.${messages.` pattern elsewhere; no other occurrences.

`replayRevoked` was also unused — revoking a link gave no confirmation at all,
since `SharedReplaysTable` had no success feedback. Added the repo's standard
`toast(t(messages.replayRevoked))` on success.

## 3. Copy button copied the note, not the link

`FormField` clones the react-hook-form field props onto its child:

```js
return react.cloneElement(child, { ...field, id: fieldId, ... });
```

That spread overwrites the `TextField`'s `value` with the form value for
`name="link"` — a field that does not exist, so the value went empty and the
copy button fell back to copying whatever the field resolved to. The link was
never in the DOM input.

Replaced with a plain `Label` + `TextField` inside a `Column`, matching the
existing working pattern in `ShareEditForm.tsx:130-134`, which renders the
share URL the same way.
